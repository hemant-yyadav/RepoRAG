# Qdrant vector storage

Qdrant stores the vectors generated by the embedding pipeline together with citation-ready payload metadata. The service uses cosine distance because it is the standard choice for normalized semantic embeddings.

## Local development

Start Qdrant from the repository root:

```powershell
docker compose up -d qdrant
```

The REST endpoint is available at `http://localhost:6333`; its dashboard is available at `http://localhost:6333/dashboard`. Data is persisted under `data/qdrant/`, which is ignored by Git.

Set `QDRANT_URL=http://localhost:6333` in `.env`. An API key is optional for this local container and can be set with `QDRANT_API_KEY` for managed Qdrant deployments.

## Storage behavior

`QdrantStore` creates the configured collection on first vector write using cosine similarity and the vector dimension from the embedding result. Each point has a deterministic UUID derived from its `chunk_id`, so unchanged chunks retain their identity.

The payload contains repository ID, chunk ID, path, language, exact source lines, symbol, chunk type, content, content hash, and small chunk metadata. Re-indexing uses repository replacement: existing points matching that repository ID are deleted before current points are upserted, preventing stale or duplicate chunks. Repository status and deletion use the same repository-scoped metadata filter.

No semantic search, hybrid search, reranking, or retrieval API is implemented in this phase.
